# 架构说明

## 总体数据流

```text
屏幕帧
  → 棋盘候选与透视定位
  → 9×10 网格/棋子圆心校验
  → 90 格概率证据
  → 合法棋局状态估计
  → 已确认局面与完整历史
  → Pikafish 搜索与风险复核
  → 点击前新帧审计
  → 不可重复落子事务
  → 连续帧确认/恢复
```

界面只展示已确认状态。视觉候选、引擎结果和鼠标事务都绑定会话与局面版本，迟到结果不能覆盖
新局面。

## 模块职责

| 模块 | 责任 |
| --- | --- |
| `app.py` | Tk 主程序、自动接管编排、线程与状态栏桥接 |
| `ui.py`, `ui_widgets.py` | 工作台布局、棋盘绘制、胜率曲线和交互组件 |
| `core.py` | 棋盘模型、FEN、走法、规则与合法性 |
| `recognition.py` | ONNX 棋盘定位、分类概率、候选区域选择 |
| `grid_geometry.py` | 平台无关网格拟合、锚点审计与坐标安全 |
| `tracking.py`, `screen_cache.py` | 连续帧跟踪、变化检测和严格缓存 |
| `automation.py` | 观察证据、合法候选估计与落子事务 |
| `autoplay_state.py` | 对局历史和待确认事务的原子持久化/恢复 |
| `engine.py` | UCI/Pikafish 生命周期和迭代结果解析 |
| `search_pipeline.py` | 搜索调度、预测、取消和可信结果选择 |
| `move_policy.py` | 风险报告与自适应安全复核 |
| `performance.py`, `vision_runtime.py` | CPU/GPU 配置与安全回退 |
| `diagnostics.py` | 有界日志、诊断事件和版本信息 |
| `winrate.py` | 红方视角胜率历史的数据模型 |

## 关键不变量

1. **视觉不变量**：一次分类高分不等于点击授权；几何与局面必须在同一新截图上成立。
2. **历史不变量**：只提交能够从已确认局面通过合法着法衔接的新状态。
3. **事务不变量**：同一事务目标点击次数不超过一次，重启后也不能重发。
4. **窗口不变量**：目标窗口不在前台或用户正在操作时不发送鼠标输入。
5. **搜索不变量**：评分、WDL、PV 和 `bestmove` 必须来自同一完整迭代结果。
6. **界面不变量**：后台线程不直接修改 Tk 控件，通过主线程队列提交会话匹配的结果。

## 视觉恢复层级

常规路径复用锁定 ROI；发生动画或不确定时逐级恢复：端点证据、完整棋盘识别、清除定位提示并
重新搜索、终局/新局检测。安全等待可以降低观察频率，但不能重复点击或把不确定状态写入历史。

起点圆心只是一种辅助证据。完整网格、全盘锚点和已解码起点一致时，单个圆心漏检可以回退到
网格交点；网格或全盘证据不足时仍拒绝点击。

## 并发模型

- Tk 主线程负责界面和最终状态提交。
- 识别、引擎搜索和自动接管运行在可取消后台任务中。
- F1 急停先设置取消状态，再恢复窗口并等待后台清理。
- 每个异步结果带会话/局面标识；提交时再次比较，过期结果丢弃。

## 扩展原则

- 优先增加通用证据，不为单个平台硬编码棋盘坐标。
- 新后端必须提供失败回退；DXcam 失败时仍可使用 Pillow。
- 新视觉特征先用于降权或复核，只有经过回归测试后才能成为点击授权条件。
- 改动跨越识别、历史、搜索和点击时，测试每层接口并增加至少一个端到端模拟回放。
